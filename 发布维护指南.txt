发布维护

公开仓库只放安装包、必要的发行元数据和说明。不要上传开发分支、完整 Git 历史或独立源码包。

更新步骤：
1. 本地改版本、打包并检查。保留旧 ZIP、哈希和本地源码标签。
2. GitHub → Releases → Draft a new release。新建版本标签，标题用版本号即可，说明写清改了什么。
3. 上传一个 -forever.zip、同名 .sha256 和 release.json。传完再发布，并以未登录身份下载核对。
4. 先由 1–2 人实机检查，再扩至 10 人。成员用 WowUp 检查更新；自动更新由成员自行开启。
5. 不覆盖已发布的同名安装包。旧版保留，回滚前提醒成员关闭 Auto Update 并开启 Ignore。

WowUp 会按发布时间选取近期 Release，不要在新版之后重新发布旧版。本仓库没有云端源码构建。GitHub 不通时，转交原 ZIP、哈希和指南，保持文件原字节。
十人安装记录留在公会私有位置，不上传账号资料。版本自报和公报回执不是安装验收，也不是已读证明。

Publishing

Keep this repository limited to installers, release metadata and documentation. Do not upload development history or standalone source packages.
Build and test locally. Create a new Release with a new version tag, one -forever.zip installer, its .sha256 file and release.json. Publish only after all assets finish uploading; then verify anonymous downloads and hashes.
Keep old versions. Do not replace a published file under the same name or publish an old version after a newer one. Pilot game checks with one or two members before all ten update. This repository does not build source in the cloud.
For a rollback, disable Auto Update and enable Ignore first. When GitHub is unreachable, distribute the original ZIP and checksum through a trusted guild channel.
